## 문제 요약

H×W 격자에서 시작점 → 목적지. 두 가지 이동이 있다.

- **걷기** — 상하좌우 인접한 길 칸으로. **비용 0**
- **마법** — 현재 칸 중심 5×5 안의 길 칸으로 워프. **비용 1**

마법 사용 최소 횟수를 구한다. 도달 불가면 −1. (H, W ≤ 1000)

## 접근

가중치가 0과 1뿐인 최단경로 → **0-1 BFS**가 정석.

내가 쓴 방식은 덱 대신 **레이어별 BFS**다. 0-1 BFS와 동치이고 복잡도도 같다.

```
bfs(cnt)   마법 cnt회로 갈 수 있는 칸을 플러드 필로 통째로 칠함
jump(cnt)  그 영역 전체에서 한 번 워프해 닿는 새 칸을 cnt+1로 표시
cnt++ 반복
```

걷기가 공짜라 "마법 k회로 도달 가능한 칸"은 연결 성분을 이루고,
그 성분 전체가 다음 워프의 출발점이 된다. 레이어 k를 전부 확정한 뒤
k+1을 만들므로 BFS의 단조성이 유지된다.

큐 3개를 쓴다 — `j`(다음 레이어 시작점), `b`(플러드 필용), `q`(워프 출발 후보).

`mapp`은 `string` 배열이라 `mapp[-1]`은 앞쪽 메모리를 string 객체로 해석해
그 안의 포인터를 따라간다. **로컬 `-O2`에서는 정답이 나오지만** 채점에서는
14개 테스트 전부 RE. ASan으로 돌리면 `global-buffer-overflow`로 즉시 잡힌다.

```bash
g++ -O1 -g -std=c++17 -fsanitize=address,undefined -o main main.cpp
```

`jump()`는 검사 순서가 처음부터 올바랐고, `bfs()`만 반대였다.

## 다른 풀이

| 방법 | 복잡도 | 비고 |
|---|---|---|
| 0-1 BFS (덱) | O(V+E) | 정석. 0비용은 `push_front`, 1비용은 `push_back` |
| 레이어 BFS | O(V+E) | 이 코드. 동등하지만 길다 |
| Dijkstra | O(E log V) | 통과는 하나 아슬아슬 (E ≈ 2.8×10⁷) |
| Union-Find 축약 → BFS | O(Vα+E) | 0비용 성분을 뭉치면 평범한 BFS가 됨 |
| 백트래킹 | 지수 | 12×12에서 이미 2억 노드 초과. 검증용으로만 |
